## Delivered
- **Auth pages:** `/login`, `/register`, `/verify-email`, `/forgot-password`; sign-out button in the header
  (also clears tenant state in Redux). Forms use React Hook Form + shadcn Field components inside Card
  containers, no `asChild` anywhere.
- **Onboarding page** `/onboarding`: renders the right step on the server (form / under review / rejected with
  reason / approved).
- **Platform approvals** `/platform/applications`: approve (two-step confirm) or reject with reason.
- **Branch setup** `/dashboard/branches`: list, create, edit; plan limit enforced inside a transaction.
- **Server:** `lib/tenant/onboarding.js`, `branches.js`, `bundle.js` (pure), `active.js`; routes in
  `docs/API_DOCUMENTATION.md`; shared zod schemas; `readJson` body guard; session endpoint now upserts
  `platformUsers`.
- **Tests:** unit, rules, integration (see above). **Docs:** ONBOARDING.md, API_DOCUMENTATION.md.

## Decisions made without you (please confirm or change)
1. Application document ID = applicant uid (one application per user; deviation from the draft schema).
2. A user who already belongs to a shop cannot apply for another (prompt: multi-tenant users only when
   explicitly authorized; the authorization path does not exist yet).
3. Placeholder plan limits: 3 branches, 10 employees, 0 AI requests. **Not a pricing decision**; Phase 17.
4. Tenant defaults: currency PKR, timezone Asia/Karachi, locale en.
5. Initial branch is always created as "Main Branch" with the application's address and phone.
6. Only OWNER manages branches (`settings:write`); no branch deactivation yet.
7. Single onboarding page instead of separate `application/` and `pending/` routes.

## Not done / limitations
- No email to applicants when a decision is made (no email provider chosen).
- No rate limiting, CAPTCHA or App Check on registration and application endpoints.
- Registration reveals that an email is already registered unless Firebase email-enumeration protection is on.
- Google sign-in, custom password-reset page (Firebase's hosted page is used) and invitation acceptance are not built
  (invitations belong with user management, Phase 5).
- Platform admin lands on `/onboarding` after login; they must open `/platform/applications` directly.
- No suspended/rejected-tenant notification UI; `requireTenantAccess` failures show the generic error page.
- Display name is not pre-filled in the application form (session has no name claim).
- Firebase plan requirements for production were not verified online: **[VERIFY]**.
